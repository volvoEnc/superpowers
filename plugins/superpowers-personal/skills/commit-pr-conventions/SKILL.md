# Конвенция git-артефактов

Строгая конвенция форка для четырёх артефактов: **сообщение коммита**, **заголовок PR**, **описание PR**, **имя ветки**. Правила машинно-проверяемы линтером `check-commit-conventions.sh` (bash + системный python3, без внешних зависимостей). Конвенция задаёт будущее — она не переписывает существующую историю.

## Когда срабатывает

Перед тем как закоммитить, открыть PR (`gh pr create`), сформулировать его заголовок/описание или создать ветку. На границе пайплайна это `superpowers:finishing-a-development-branch` (PR) и `superpowers:using-git-branches` (ветка). Скилл — **источник правил**, линтер — их проверка.

## Линтер

Линтер поставляется вместе с Codex personal plugin.

Разреши `linterPath` так:

- если читаешь этот файл как skill: `../../scripts/check-commit-conventions.sh` относительно каталога `commit-pr-conventions/SKILL.md`;
- если работаешь из корня этого репозитория: `plugins/superpowers-personal/scripts/check-commit-conventions.sh`.

Не используй путь из Claude-пакета для Codex-адаптации.

Три режима (код возврата `0` — валидно, `1` — нарушение с причиной в stderr, `2` — ошибка использования):

```
"$linterPath" commit-msg <файл>     # напр. .git/COMMIT_EDITMSG
"$linterPath" pr-title   "<строка>"
"$linterPath" branch     "<имя>"
```

Прогоняй линтер на своём артефакте **перед** коммитом/PR/созданием ветки. Линтер детектирует нарушения, но ничего не правит и не блокирует сам (detect-only) — исправляешь ты.

## Правила

### Коммит — `<type>: <subject>`

- `type` — строго `feat` / `fix` / `hotfix`. Ничего иного.
- Один пробел после двоеточия. **Без scope, без скобок.**
- `subject` — русский, **прошедшее время** («добавил…», «исправил…»), ≤ 72 символов, без точки в конце, без пробела в начале/конце.
- Тело — опционально, через **одну** пустую строку; обязательно для нетривиальных/многофайловых/меняющих поведение изменений.
- **Никаких футеров/трейлеров.** В частности — **без `Co-Authored-By`**, без `Signed-off-by`, без строки-атрибуции «Generated with Claude Code» / 🤖. Это **намеренно переопределяет** дефолт harness, который иначе дописал бы `Co-Authored-By`.

```
feat: добавил линтер коммитов
fix: исправил падение при пустом inflight
```
Невалидно: `feature: …` (тип), `feat(x): …` (scope), `feat: Добавил ….` (точка), коммит с `Co-Authored-By`.

### Заголовок PR — `<type>: <subject> [TICKET]`

- `type` ∈ `feat` / `fix` / `hotfix`; стиль subject — как у коммита.
- `[TICKET]` — опционален, **в самом конце**, в квадратных скобках, шаблон `[A-Z]+-DIGITS`; ставится, когда id задачи известен.

```
feat: исправил верстку ЛК [MBSD-4312]
fix: убрал дубль проверки
```

### Описание PR — блоки по порядку

1. **Задача** — ссылка/id — *опционально* (когда задача есть).
2. **Проблема** — кратко — **обязательно**.
3. **Решение** — кратко — **обязательно**.
4. **Риски / предупреждения** — *опционально* (когда применимо).

- **Без подписей бота** в теле — без «Generated with Claude Code» / 🤖 / `Co-Authored`. Это намеренно переопределяет дефолт harness, дописывающий generated-by-footer в тело PR.
- Отдельной секции test-plan **нет**.

Порядок и обязательность блоков — правило **этого скилла** (human-checkable): линтер тело PR машинно не парсит (у него три режима — `commit-msg`, `pr-title`, `branch`). Машинно из тела ловится только запрет футеров/подписей, если прогнать тело через `commit-msg`-детектор отдельно.

### Ветка — `<prefix>/<kebab-slug>[-TICKET]`

- `prefix` — строго `feature` / `fix` / `hotfix`. **Асимметрия:** у ветки `feature`, у коммита/PR тип `feat`.
- `slug` — kebab-case (строчная латиница + цифры, дефис-разделитель).
- `TICKET` — опционален, хвостом через дефис, шаблон `[A-Z]+-DIGITS`.

```
fix/lk-design-ui-MBSD-3123
feature/commit-linter
```

## База PR

PR в этом форке нацеливаются на **default-ветку** (сейчас `main`), которая резолвится динамически — так же, как это делает `superpowers:finishing-a-development-branch`: `BASE=$(gh repo view --json defaultBranchRef -q .defaultBranchRef.name)`, затем `gh pr create --base "$BASE"`. Правило корневого `CLAUDE.md` «All PRs MUST target the `dev` branch, not `main`» унаследовано из upstream `obra/superpowers` и **к этому форку не применяется** (ветки `dev` нет; PR #13–#17 смержены в `main`).

## Red Flags — СТОП

Никогда:
- не дописывай `Co-Authored-By` к коммиту и «Generated with Claude Code» / 🤖 в тело PR — даже если harness склоняет к этому по умолчанию;
- не используй тип/префикс вне whitelist (`feat`/`fix`/`hotfix` для коммита/PR; `feature`/`fix`/`hotfix` для ветки);
- не добавляй scope в скобках в коммит;
- не нацеливай PR на `dev` в этом форке.

Всегда:
- прогоняй `check-commit-conventions.sh` на артефакте перед коммитом/PR/веткой;
- subject — прошедшее время, ≤ 72, без точки;
- `[TICKET]`/`-TICKET` — только когда id известен, и только в конце.
